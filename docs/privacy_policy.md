# 隐私说明（本地开发预览版）

## 1. 适用范围与当前状态

本说明适用于“个性化风格情感伴侣 AI”项目当前的本地开发预览版本，用于如实说明代码已经具备的数据处理能力和仍未实现的保护措施。当前版本面向开发、联调和功能验证，不应作为可直接公开运营的生产服务。

本项目生成的是 AI 模拟内容，不代表被模拟人物本人，也不得用于骚扰、跟踪、冒充或侵犯他人隐私。使用者只能导入自己拥有或已经获得合法授权的数据。

## 2. 当前处理的数据

当前版本可能处理以下数据：

- 人物资料：人物名称、关系类型和自定义关系名称。
- 导入资料：用户主动选择的微信、QQ 或其他聊天文件、数据库文件、压缩包、文档、图片、音频、视频及其文件名、大小、类型和校验值。
- 对话数据：用户发送给 AI 的文本消息、所选供应商与模型，以及供应商返回的文本和用量信息。
- 服务配置：存储目录、模型服务地址、允许使用的模型和服务端 API Key 环境变量。

当前里程碑已完成通用 TXT、JSON、JSONL、CSV 和 XML 聊天记录的内容探测、统一消息标准化、多文件导入预览、参与者角色映射和预览修正，同时具备人物创建、分片上传、文件完整性校验、供应商目录和文本聊天网关。参与者映射和用户修正随导入清单加密保存。P0-30/P0-31 已提供受支持微信和 QQ 明文 SQLite 消息表目录的只读解析，P0-32/P0-33 已提供带 manifest v1 的微信和 QQ ZIP 备份包安全解析；P2-03 已提供仅基于人物文本的风格画像统计，P2-04 已提供默认待审核的长期记忆候选统计，P2-05 已提供仅针对已审核候选的本地有界检索，P2-06 已提供多模态能力门控，P2-07 已提供能力门控训练任务的本地预估、加密状态与取消框架；R1-01 现已将画像、长期记忆和版本化稀疏索引按 owner/persona 使用 AES-GCM 持久化，并提供独立查询、审核、检索和人物删除级联 API；另有不占用路线图编号的本地媒体元数据检测补充。P2-07 的确定性训练 Provider 仅存在于测试模式，当前没有真实供应商微调适配器可在开发或生产环境接收训练文本。

P1-03 通用 HTML 解析仅提取识别到的消息容器中的发送者、时间、正文和消息类型字段，脚本、样式和模板内容不会作为对话数据导入。P3-08 移动端授权管理仅操作已选人物的授权元数据；创建时绑定供应商、模型、数据类别、用途、作用域和预计费用上限，撤回前需要二次确认，客户端不会读取或上传媒体正文。P3-09 移动端文本会话按 owner/persona 隔离并使用认证加密 SQLite 保存；服务端只在 Provider 成功返回非空文本后同时写入用户消息和对方回复，Provider 失败不会伪造或残留半条消息。P3-10 移动端隐私管理仅展示 owner 级导出摘要，不保存完整导出 JSON、原始正文或访问令牌；人物删除前必须二次确认，成功后级联清理本地受控导入、授权、训练任务和会话。会话随人物删除级联清理，并纳入 owner 元数据导出；本任务不包含流式传输或第三方媒体动作。R2-02 当前支持在有效 P1-10 授权、目录能力和已配置 OpenAI-compatible 适配器同时满足时进行图像语义分析、显式音频转写或配置端点的视频语义分析；响应仅返回受限描述/转写文本和用量元数据，不返回媒体字节或临时路径。OCR 专用结构化提取和第三方删除仍未实现。

按原始任务编号，P1-05 通用 SQLite、P1-06 微信原生数据库和 P1-07 QQ 原生数据库只读取用户主动选择的目录快照，识别常见消息表字段并输出规范化记录；QQ 支持 `.db`、`.sqlite`、`.sqlite3` 及 WAL/SHM sidecar，源目录不会被写入，单个数据库文件、加密库和未知 schema 会明确拒绝或返回密钥需求。附件引用会统一为元数据，不读取媒体文件内容；P1-08 DOCX 和 P1-09 PDF 仅提取对话文本，不执行文档脚本、不发送文档原文给第三方模型。P1-10 提供按人物、供应商、模型、数据类别和授权范围精确匹配的第三方媒体处理授权记录、查询与撤回接口；本地上传或保存媒体引用不等于同意向第三方发送。P2-01 已提供模型能力、上下文长度、隐私元数据、价格来源和刷新时间，并允许通过服务端配置生成成本估算；未配置价格时不会返回伪造估算。PDF 优先使用可选 `pypdf`，回退仅读取受限文本操作符并支持 UTF-16 十六进制文本；加密文档、损坏文档、页数超限和无对话内容会拒绝解析。

当前代码没有实现使用统计、广告标识或行为分析数据的自动采集。

## 3. 数据如何使用和流转

- 人物资料和导入文件用于本地功能验证，并为后续经过用户确认的解析、画像和学习流程提供输入。
- 上传内容由当前运行的 Python 服务写入配置的数据目录。默认启动方式仅监听本机回环地址；真机开发联调只能通过开发模式的私有 IP TLS 配对配置访问，当前服务不信任 `X-Forwarded-For` 等代理头。
- 当用户发起模型对话时，文本消息会发送给用户选择且由服务端配置的模型供应商。供应商会按其自身的隐私政策、服务条款和数据保留规则处理这些内容。
- 原始图片、音频或视频不得发送给第三方模型供应商，除非存在针对当前人物、供应商、模型、数据类别、用途和授权范围的有效 P1-10 consent 记录。授权记录保存预计费用并支持 owner 级查询与撤回；撤回只阻止未来处理，不代表第三方已接收数据会自动删除。原始媒体仍需按供应商、用途、范围和预计费用进行逐次告知并取得授权。P1-05 只保存媒体引用元数据，不代表已完成 OCR、ASR、视觉分析或媒体上传。R2-02 的 `POST /api/v1/imports/{import_id}/media-analysis` 会在服务端再次确认同意后，才把受限大小的已完成导入文件临时传给已配置且显式声明能力的适配器；图像走视觉接口，音频走标准 `/audio/transcriptions` multipart 接口，视频走部署者配置的 Provider 专用 multipart 路径，结果只返回归一化描述/转写文本。未声明 audio/video 能力或缺少视频端点配置的模型会明确返回 `capability_not_supported` 或配置错误。仅上传到本地服务不等于同意向第三方发送。
- P2-07 训练预估只在本地受控临时目录中从已完成导入流式生成 JSONL，并在响应或提交后删除；它只返回样本数量、摘要和成本，不返回原始正文或临时路径。向 Provider 提交前必须再次验证当前人物的独立训练授权：`data_category=persona_text`、`purpose=fine_tuning`、`authorization_scope=fine_tuning:{import_id}`、Provider、模型和授权成本上限均须精确匹配。训练样本只来自已接受的 `persona` 消息；用户、其他参与者、未审核和已拒绝消息不会作为目标。每份训练授权只能提交一次，防止单次成本同意被重复消费。
- 训练任务的持久化记录只包含加密的任务 ID、诊断 ID、人物/导入/授权/模型引用、样本和摘要、估算成本、状态、进度、可重试标记、红化失败码、`submission_started` 外发意图、`local_cleanup_failure_code` 本地临时明文清理失败码、Provider 工件 ID 和有限评测摘要；不保存训练正文、临时数据集路径、凭据或完整 Provider 响应。外发意图会先于 Provider 接收文本写入，且微调适配器必须能按本地任务 ID 对账，避免远端 ID 持久化失败后把可能已接收的训练任务误当作未提交。只有 Provider 返回非空工件 ID 与评测对象时任务才可完成；本地清理失败码不会覆盖 Provider 已验证的实际完成、失败或取消状态。授权撤回会阻止尚未开始的后续外发；已由第三方接收的数据仍受该 Provider 的删除和保留规则约束。
- `GET /api/v1/imports/{import_id}/media-inspection` 只针对已完成的 owner 范围导入，在服务器控制的临时路径中一次解密一个清单文件边界，以验证图片格式/尺寸或音频、视频的格式、时长和编码元数据；每个文件写入前都会检查临时盘可用空间，正常路径会在响应前删除临时明文，响应不包含原始字节或本地路径，并固定标记 `provider_transfer: false`。若空间不足或删除失败，接口会返回稳定错误而不是伪造成功；服务启动时会重试清扫此受控目录中的残留临时文件。该功能不执行 OCR、ASR、图片或视频语义理解，不调用模型，也不向第三方发送媒体。图片检测需要可选 Pillow 依赖；音频和视频检测还依赖本机 `ffprobe`，缺失或检测失败会明确拒绝而不会伪造成功。
- P2-07 不复用媒体检测响应中的 `provider_transfer` 字段；训练文本只有在目录 `fine_tuning` 能力、训练价格、已配置微调适配器和独立授权均通过后，才会由 Provider 网关接收。能力缺失时创建接口返回稳定的 `capability_not_supported`，不会降级成聊天调用或伪造训练成功。完成状态只在响应中的非空 `artifact_id` 和非空 `evaluation` 均已由 Provider 返回后成立；这两个字段是有限结果元数据，不包含训练正文。
- 使用本地模型服务时，数据是否离开设备取决于用户配置的实际服务地址；项目不能仅凭供应商名称保证数据始终留在本机。

本项目维护者不以出售或出租用户数据为目的，但用户选择第三方模型服务会产生上述必要的数据传输。当前版本未集成云存储、广告或独立统计服务。

## 4. 当前已有的保护措施

当前代码已经实现以下基础保护：

- 文件由服务端生成的标识定位，并校验存储路径，阻止客户端文件名控制实际存储路径或进行目录穿越。
- 分片上传限制单片大小，并使用 SHA-256 校验分片；完成导入时可校验整个文件摘要。
- HTTP 请求体和导入任务总大小受配置限制，默认单个导入任务上限为 3 GiB。
- 静态文件仅从明确允许的目录提供，跨域请求只允许配置的来源。
- API Key 仅从服务端环境变量读取，不由浏览器端提交，也不通过供应商目录接口返回。
- R2-02 图像分析使用服务器控制的临时文件和受限 data URL，音频转写和视频语义分析使用同一临时文件边界通过 multipart 上传；有效授权撤回、模型能力缺失、文件超限、Provider 不可用和临时存储失败都会返回稳定错误，不会降级为聊天调用或伪造分析成功。移动端只保存分析结果元数据和错误状态，不保存原始媒体字节。

这些措施不能替代生产环境所需的加密、账户隔离、授权、审计、备份和安全运维。

## 5. 当前尚未实现的保护能力

为避免把设计目标误认为现有能力，当前限制明确如下：

- 当前版本尚未实现静态数据加密的完整覆盖，P0-07 已将人物名称、关系和创建时间等内容字段保存为加密 SQLite 字段，P0-08 已将导入任务和上传清单保存为同一事务中的加密 SQLite 字段；随机服务端人物和导入 ID 作为非秘密索引明文保存，P0-06 已将上传分片和合并对象接入 AES-GCM 加密存储。
- 默认本地服务使用回环 HTTP，仅适合本机调试。真机开发联调必须配置四个 `PAST_PARTNER_DEV_DEVICE_*` 变量，由服务端校验 RFC1918/IPv6 ULA 私有地址、证书 IP SAN 并以 TLS 1.2+ 启动；设备配对令牌不进入 CORS allow-headers，也不会写入日志。配对令牌是开发联调凭据，不是公网安全机制；不得把服务暴露到公网、通过不受控代理转发或把真实令牌提交到仓库。设备会话最长 1 小时，轮换令牌会使旧设备会话失效；生产 owner 会话仍使用独立的 `PAST_PARTNER_OWNER_BOOTSTRAP_TOKEN`。
- 加密元数据默认由同一进程内共享的 SQLite `MetadataStore` 负责迁移、连接和事务边界；也可通过服务端 `PAST_PARTNER_METADATA_BACKEND=postgresql`（`postgres` 为兼容别名）切换到 PostgreSQL 适配器。PostgreSQL DSN 只从 `PAST_PARTNER_METADATA_DSN` 读取，不写入日志、响应或客户端配置；连接池上下限由服务端变量控制并在启动时限制范围。未知后端、缺少 DSN 或缺少 PostgreSQL 驱动都会明确失败，不会静默回退或伪装成 SQLite。对象字节存储仍由独立的 `PAST_PARTNER_STORAGE_BACKEND` 选择；P4-04 的 S3-compatible 适配器使用同一逻辑 key 边界，生产 endpoint 必须为 HTTPS，服务端凭据不会进入客户端或日志。P4-05 的 KMS-backed 主密钥源仅在显式配置 key ID 后启用，使用 AWS-compatible KMS 以加密/解密 32 字节数据密钥，本地仅保存 KMS 密文 blob；生产 endpoint 必须为 HTTPS，不记录 KMS endpoint、凭据、key ID、密文或明文密钥。P4-06 的任务队列复用同一元数据后端，路由/租约字段用于抢占，任务载荷和结果使用 AES-GCM 加密；租约、重试和失败只保存有界状态码，不保存异常文本、供应商响应或原始数据。worker 不会由服务自动启动，也不代表已经完成多用户账户隔离或多节点运维。
- 模拟器或 Android ADB reverse/port-forward 可以继续使用回环 HTTP，且不发送设备配对 header；该方式不等同于真机直连，不应把端口转发暴露给不受控网络。
- 当前版本保留本地 owner 的 Bearer 会话，同时在 development/test 模式提供受限的本地账户主体（subject、tenant、admin/member role）和独立会话。人物/导入/上传仍以认证主体的 `owner_id` 隔离；不同本地账户无法读取或删除彼此资源。该本地账户入口不是注册系统，不接收生产凭据，不适合直接暴露到公网或多人共享环境。
- P4-07 已为本地会话增加 `owner:read` 和 `owner:write` scope：读取接口需要前者，写入/删除接口需要后者，scope 缺失会返回拒绝；scope 与会话一起持久化并在篡改或未知值时 fail closed。R1-03 OIDC 登录接受静态或 HTTPS URI JWKS，仅验证 RS256 ID Token，未知 `kid` 刷新远程密钥时受有界间隔和响应大小限制；按 issuer、subject 和 tenant 建立加密本地主体并签发独立来源的 Bearer session，token 不落盘。远程 discovery、刷新令牌、账户恢复、管理员 API 和正式租户管理仍未提供。迁移前创建的静态 OIDC 身份缺少 issuer 历史信息，会被保留在 `local` 命名空间，不自动迁移到新的 OIDC issuer。
- 当前版本不把原始导入或对话正文伪称为已匿名化；导入和对话内容仍可能包含本人及第三人的敏感信息。R1-02 的 owner 删除回执仅保留去标识化的数量和时间，不包含 owner、正文、路径或凭据。
- R1-02 已提供成功标准化导入的可配置保留期清理、原始载荷完整归档导出和当前本地 owner 的级联删除；保留期默认关闭，`PAST_PARTNER_NORMALIZED_RETENTION_SECONDS` 与原始终态清理均受五年硬上限约束。账户删除要求请求体明确发送 `{"confirm":"DELETE"}`，会删除本地控制的原始对象、导入清单、归一化入口、画像、长期记忆、向量、会话、授权、训练元数据、用量、余额账本和任务载荷，并返回不含 owner、正文、路径或凭据的匿名删除回执。当前本地 owner 的技术壳保留以允许开发服务重新建立会话；第三方 provider 副本和已提交的外部训练作业不被伪称为已删除，会在限制字段中返回。
- P4-08 已提供 owner 范围的加密追加式业务审计基础：成功的人物/导入删除、第三方授权确认与撤回、已确认的训练取消会记录有限事件元数据，并可由有 `owner:read` scope 的主体通过 `GET /api/v1/audit-events` 分页读取。审计事件只允许固定的 provider/model/scope/数量/原因键，原始正文、媒体、文件路径、token、API Key 和完整 Provider 响应不会写入；接口不支持修改或删除。R2-04 Task 3 又增加 owner 内追加序号、前链哈希和事件哈希，读取接口及 `scripts/verify_audit_chain.py` 会报告 `audit_chain_gap`/`audit_chain_mismatch`；这仍属于应用级最小证明，不等同于合规 WORM/监管审计，外部不可变存储、SIEM、泄露通知、计费或监控仍未接入。HTTP 访问日志仍仅记录方法、路由模板、状态、对端类别和诊断 ID，不记录 token、query、body、客户端 IP 或异常堆栈。
- P4-09 已提供 owner 范围的加密实际用量账本：成功聊天响应中有规范化 provider usage 时，服务按当前目录价格保存 token/media 用量、provider/model、计费模式、价格状态和有限费用字段，并通过 `GET /api/v1/usage` 只读分页读取。provider request reference 只保存不可逆指纹；原始消息、完整 provider 响应、凭据和 API Key 不进入账本。缺少 usage 或价格时分别记录 `usage_unavailable`/`pricing_unavailable`，不伪造金额；BYOK 仅展示 provider 侧估算，本地模型标记为 `local_compute`，平台扣款字段为零。P4-09 本身不代表已实现支付、订阅、余额、发票、退款、税务、自动限额、收入结算或供应商最终账单对账。
- R2-04 Task 1 已提供 owner 范围的余额账本基础：账务载荷使用 AES-GCM 加密，方向、币种、金额和时间等有限索引列用于事务校验，幂等键只以 SHA-256 摘要建立唯一索引；入账和扣账只接受整数最小货币单位，owner 级操作键幂等，余额不足时在同一事务中拒绝且不产生部分写入；`GET /api/v1/billing/balance` 和 `GET /api/v1/billing/entries` 需要 `owner:read`，流水响应不会返回内部幂等键。该切片没有支付回调、客户端入账、订阅、充值、退款、发票、税务或供应商账单对账能力，不应被解释为真实支付系统。
- R2-04 Task 2 已提供 owner 范围的加密订阅权益快照：状态限定为 `trial`、`active`、`past_due` 或 `cancelled`，Provider 事件键和订阅标识的查询索引仅保存 SHA-256 摘要，原始订阅标识仅存在 AES-GCM 加密事件/快照载荷中，并由 owner 认证读取。事件键按 Provider 全局幂等，每个 Provider 订阅摘要只能绑定一个 owner；相同时间戳的不同状态会拒绝，取消或周期过期后才允许切换到更新的订阅标识。`GET /api/v1/subscription` 需要 `owner:read`，只返回计划、Provider 标识、周期边界、状态和当前是否享有权益，不返回 Provider 事件键。支付 Provider webhook、签名校验、扣款、续费、退款和真实订阅权益同步尚未接入，服务只接受已完成外部签名验证的内部事件。
- P4-10 已提供进程内监控基础：`GET /api/v1/health` 是不需要认证的存活检查，`GET /api/v1/ready` 只检查元数据后端并以 `200`/`503` 返回 `ready`/`not_ready`，`GET /api/v1/metrics` 需要 `owner:read`。指标只保留按方法、规范化路由模板和状态码聚合的请求计数及进程内 in-flight 数，不记录 owner、请求 query/body、文件路径、token、API Key、供应商响应或异常文本；指标随进程重启归零。该切片不提供外部 Prometheus 推送/抓取、告警、追踪、日志外发、供应商或对象存储健康探测、跨进程聚合、持久化保留或合规监控。
- R1-04 第一切片提供独立 `python -m src.worker`/`companion-worker` 进程入口，仍复用共享元数据和主密钥配置；worker 不会由 API 服务自动启动，生产模式不注册隐式业务 handler，启动日志不记录 payload、DSN、密钥或本地路径。broker 契约只在同一元数据事务中追加不含 owner、正文、密钥、供应商响应或路径的任务通知 outbox，发布失败仅保留有界错误码和重试时间；当前内存 broker 仅用于测试去重、ack/nack 和可见性恢复。worker 观测切片只把 worker/task 类型、固定生命周期结果、时间、耗时和稳定失败码写入有界共享表，并支持内部高失败率/无心跳告警计算；不含 owner、任务载荷、异常文本、provider、凭据或路径，也未实现 Redis、RabbitMQ、云消息服务、外部指标推送/抓取、追踪、日志外发和 SIEM。
- Phase 5 发布准备只提供 Android 的显式 StoreRelease 签名门禁、版本/传输静态检查和可审计的 APK 清理命名规则。keystore 路径、密码和别名只从构建进程环境读取，不进入客户端、日志或 Git；普通本地 debug/release 验收路径不代表商店签名。Windows 环境下 iOS 仅执行 Info.plist 版本与 ATS 静态检查，不代表已完成 Xcode archive、App Store 签名、发布或真机验证。

当前代码已提供 P0-05 AES-256-GCM 认证加密服务，P0-06 已接入上传分片和合并对象，P0-07 已接入人物内容字段仓储并自动迁移旧人物 JSON，P0-08 已接入导入任务/清单事务仓储并自动迁移旧导入 JSON，P0-09 已接入本地 owner 会话和 owner 归属校验，P0-29 已提供人物级导入级联删除；随机人物和导入 ID 仍是明文非秘密索引。R1-02 已补充成功标准化数据的保留期、原始载荷完整归档导出和 owner 级联删除；R1-03 第二阶段补充静态/HTTPS URI JWKS OIDC 登录、有限密钥轮换、加密本地账户主体和跨账户资源隔离，但远程 discovery、刷新令牌、账户恢复、正式租户管理、合规 WORM、外部 SIEM 和审计管理界面仍未提供。人物级删除会清理该人物的元数据及其 owner 名下的导入任务、清单、上传分片和合并文件；owner 级删除会在确认后清理本地受控数据并返回匿名回执，但不宣称已删除第三方 provider 副本或外部训练作业。

## 6. 保留与删除

默认情况下没有自动清理期限。设置 `PAST_PARTNER_RAW_RETENTION_SECONDS` 为 1 到五年内的秒数后，每次服务启动会清理当前 owner 名下更新时间早于阈值且状态为 `failed` 或 `cancelled` 的导入，同时删除对应的加密分片、合并对象、清单和元数据；设置 `PAST_PARTNER_NORMALIZED_RETENTION_SECONDS` 后，服务只清理已经完成一次完整预览/归一化、且 `normalized_at` 早于阈值的导入。两个设置均为 `0` 时关闭，重复预览不会刷新成功归一化时间锚点。

当前版本提供 owner 级元数据 JSON 导出和 `GET /api/v1/data-export/archive` ZIP 归档导出。归档在服务端磁盘上按固定块生成，包含版本化 manifest、人物/导入/清单/画像/记忆/会话/训练元数据和可恢复的原始 payload；manifest 同时声明归档版本、范围、原始对象数量和原始字节数，不会把 3 GiB 文件一次性放入内存。两种导出均明确列出未包含的 provider-side 数据和审计记录。`POST /api/v1/data-deletion` 只接受当前已认证 owner，删除前会拒绝处理中导入和训练任务；删除失败不生成成功回执。人物级删除仍可单独使用，授权撤回仅影响未来处理，不代替第三方删除流程。

## 7. 第三方模型与凭据

当前运行时适配器已覆盖 OpenAI、Anthropic、Google Gemini、DeepSeek、小米 MiMo、阿里通义千问、Ollama 和自定义 OpenAI-compatible 服务。OpenAI-compatible 供应商共享同一兼容协议适配器，Anthropic 与 Gemini 使用各自的原生文本接口。只有已配置的供应商和允许的模型才能处理请求。

自定义 HTTP 目前仅存在于供应商目录中，尚未实现可用的运行时适配器。目录中可见不代表已经能够发起请求；对应插件 SDK 和测试完成前，该选项不能标记为可用。P2-02 的适配器默认只支持文本 `chat`；R2-02 仅为兼容协议适配器增加了明确声明能力的图像分析、显式音频转写和配置端点的视频语义分析，不代表已经具备 OCR、流式、Embedding 或微调能力。P2-07 不会把上述目录条目或已配置聊天适配器自动升级为可训练；默认开发和生产目录没有 `fine_tuning` 声明，只有测试模式内的确定性适配器用于验证 API 合同，绝不传输给外部供应商。

发送给第三方模型供应商的数据可能包括所选模型、对话角色和文本消息。项目无法代替供应商承诺其存储地点、保留时间或训练用途；使用前应阅读相应供应商的最新条款。P2-01 的价格来自供应商或部署者维护的配置，带有来源和刷新时间，属于估算而非最终账单；供应商价格和政策均可能变化，应以供应商公布的信息为准。

API Key 仅从服务端环境变量读取。当前前端不接收、保存或展示 API Key。部署者仍需负责保护运行环境、进程权限和日志，避免凭据通过其他方式泄露。

## 8. 微信、QQ 数据库与学习功能边界

P0-30 已提供微信 3.x/4.x 明文 SQLite 数据库目录的只读解析；P0-31 已提供 QQ 通用消息表明文 SQLite 数据库目录的只读解析；P0-32/P0-33 已提供带 manifest v1 的微信和 QQ ZIP 备份包安全解析。P2-03 已提供基于规范化消息的风格画像统计；P2-04 已提供基于证据的长期记忆候选和审核状态；P2-05 已提供不依赖供应商的本地有界稀疏向量检索；P2-06 已提供发送前的供应商/模型能力门控；P2-07 已提供受限数据集、精确授权、成本预估、加密任务状态和取消框架。R1-01 已将画像、长期记忆和版本化稀疏索引按 owner/persona 使用 AES-GCM 加密持久化，并提供人物范围查询、审核、检索和删除级联 API；检索仍不调用真实 embedding 或第三方模型。数据库和备份包功能必须遵守以下边界：

- 仅处理用户主动选择并有权使用的数据；数据库、WAL 和 SHM 文件应先形成一致的只读快照，再进行解析。
- 当前版本仅接受明文 SQLite 数据库目录和已识别的消息表 schema；单个 `.db`、加密数据库和未知 schema 会拒绝解析；微信或 QQ 私有备份和未实现的媒体表同样会拒绝解析，不会自动提取、猜测或持久化密钥。后续若接入密钥提取，必须作为单独的、用户明确授权的本地步骤执行；密钥只允许短暂存在于进程内存中，不得写入日志、配置或持久化文件。
- 微信或 QQ ZIP 备份必须包含对应平台的根目录 manifest v1；条目数量、单条目大小、总展开大小、压缩比和路径都会在解压前及解压时校验。路径穿越、符号链接、重复条目、嵌套 ZIP、未被 manifest 覆盖的文件和不支持的内部格式会拒绝解析，不会使用 `extractall`，也不会把私有加密备份误报为成功。
- 训练、画像生成、记忆候选生成或外部模型处理开始前，必须说明使用的数据范围、处理位置、供应商和预计费用，并再次取得用户确认。P2-04 的候选提取只在本地运行，默认标记 `needs_review`，不会把未审核候选当作事实或发送给第三方。
- P2-05 检索只接受 `accepted` 候选，默认限制 `persona`/`user` 说话人范围，并强制候选数、token 总量和可选时间窗口预算；返回内容只包含有限证据文本和来源记录 ID。原始查询不会写入结果，只保留用于审计关联的 SHA-256 指纹；本地稀疏评分不等于真实 embedding，也不会自动向第三方模型发送数据。
- P2-06 的 `POST /api/v1/consents/{consent_id}/authorize` 只在活动授权、精确 provider/model/数据范围和目录能力声明同时匹配时返回 `authorized=true`；能力缺失、授权撤回或范围不匹配会拒绝。目录能力是部署者维护的声明，不保证供应商实际处理地点、保留期或训练用途；该接口本身不传输媒体。
- 任何训练或模拟结果都不能用于主动联系、欺骗或代表被模拟人物作出现实承诺。

## 9. 使用者权利与责任

在当前本地开发形态下，使用者可以通过控制本地数据目录和模型配置决定是否继续处理数据；人物、导入任务、清单元数据、会话、媒体授权记录、余额账本和订阅快照可以通过 owner 级 API 导出，移动端隐私页面提供不含原始正文的数量摘要。单个导入、人物级导入数据和授权记录可以通过对应 API 删除或撤回；余额账本、订阅快照及订阅事件仅随 owner 级删除清理，当前没有单独的订阅删除接口。移动端人物删除入口会在二次确认后调用人物级删除。R1-02 已提供元数据 JSON、包含受控原始载荷的 ZIP 归档，以及带 `{"confirm":"DELETE"}` 确认的 owner 级删除；第三方 provider 副本和外部训练作业仍须按各自服务的删除与保留规则处理。

使用者应避免导入无权处理的第三方数据，并妥善保护运行设备、数据目录和模型凭据。设备配对仅用于受控私有网络开发联调；不得把开发配对配置当作公网部署的身份验证或访问控制。
