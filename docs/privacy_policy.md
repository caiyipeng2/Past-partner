# 隐私说明（本地开发预览版）

## 1. 适用范围与当前状态

本说明适用于“个性化风格情感伴侣 AI”项目当前的本地开发预览版本，用于如实说明代码已经具备的数据处理能力和仍未实现的保护措施。当前版本面向开发、联调和功能验证，不应作为可直接公开运营的生产服务。

本项目生成的是 AI 模拟内容，不代表被模拟人物本人，也不得用于骚扰、跟踪、冒充或侵犯他人隐私。使用者只能导入自己拥有或已经获得合法授权的数据。

## 2. 当前处理的数据

当前版本可能处理以下数据：

- 人物资料：人物名称、关系类型和自定义关系名称。
- 导入资料：用户主动选择的微信、QQ 或其他聊天文件、数据库文件、压缩包、文档、图片、音频、视频及其文件名、大小、类型和校验值。
- 对话数据：用户发送给 AI 的文本消息、所选供应商与模型，以及供应商返回的文本和用量信息。
- 服务配置：存储目录、模型服务地址、允许使用的模型和服务端 API Key 环境变量。

当前里程碑已完成通用 TXT、JSON 和 JSONL 聊天记录的内容探测、统一消息标准化、单文件导入预览和导入后参与者角色映射，同时具备人物创建、分片上传、文件完整性校验、供应商目录和文本聊天网关。参与者映射随导入清单加密保存。微信或 QQ 专用数据库、图片/音频解析、画像生成、长期记忆、向量检索和真实模型训练仍属于后续功能，不能因文件上传成功而视为已经完成。

当前代码没有实现使用统计、广告标识或行为分析数据的自动采集。

## 3. 数据如何使用和流转

- 人物资料和导入文件用于本地功能验证，并为后续经过用户确认的解析、画像和学习流程提供输入。
- 上传内容由当前运行的 Python 服务写入配置的数据目录。默认启动方式仅监听本机回环地址，但修改监听地址或通过代理对外提供服务会改变这一边界。
- 当用户发起模型对话时，文本消息会发送给用户选择且由服务端配置的模型供应商。供应商会按其自身的隐私政策、服务条款和数据保留规则处理这些内容。
- 原始图片、音频或视频不得发送给第三方模型供应商，直至项目完成按供应商、用途、范围和预计费用进行逐次告知并取得授权的功能。仅上传到本地服务不等于同意向第三方发送。
- 使用本地模型服务时，数据是否离开设备取决于用户配置的实际服务地址；项目不能仅凭供应商名称保证数据始终留在本机。

本项目维护者不以出售或出租用户数据为目的，但用户选择第三方模型服务会产生上述必要的数据传输。当前版本未集成云存储、广告或独立统计服务。

## 4. 当前已有的保护措施

当前代码已经实现以下基础保护：

- 文件由服务端生成的标识定位，并校验存储路径，阻止客户端文件名控制实际存储路径或进行目录穿越。
- 分片上传限制单片大小，并使用 SHA-256 校验分片；完成导入时可校验整个文件摘要。
- HTTP 请求体和导入任务总大小受配置限制，默认单个导入任务上限为 3 GiB。
- 静态文件仅从明确允许的目录提供，跨域请求只允许配置的来源。
- API Key 仅从服务端环境变量读取，不由浏览器端提交，也不通过供应商目录接口返回。

这些措施不能替代生产环境所需的加密、账户隔离、授权、审计、备份和安全运维。

## 5. 当前尚未实现的保护能力

为避免把设计目标误认为现有能力，当前限制明确如下：

- 当前版本尚未实现静态数据加密的完整覆盖，P0-07 已将人物名称、关系和创建时间等内容字段保存为加密 SQLite 字段，P0-08 已将导入任务和上传清单保存为同一事务中的加密 SQLite 字段；随机服务端人物和导入 ID 作为非秘密索引明文保存，P0-06 已将上传分片和合并对象接入 AES-GCM 加密存储。
- 默认本地服务使用 HTTP；传输是否加密取决于部署方是否配置 HTTPS，以及所选模型服务地址是否使用 HTTPS。
- 当前版本提供单一本地 owner 的 Bearer 会话、人物/导入/上传 owner 归属和未授权拦截；开发模式仅允许回环地址初始化会话，生产模式需配置 `PAST_PARTNER_OWNER_BOOTSTRAP_TOKEN`。尚未接入 OIDC/OAuth2、多用户账户、细粒度角色、审计和公网部署所需的完整访问控制，不适合直接暴露到公网或多人共享环境。
- 当前版本尚未实现数据匿名化或脱敏，导入和对话内容可能包含本人及第三人的敏感信息。
- 当前版本尚未提供自动保留期清理、数据导出或级联删除功能。
- 当前版本尚未提供生产级审计日志、泄露通知流程或监管报告自动化能力。

当前代码已提供 P0-05 AES-256-GCM 认证加密服务，P0-06 已接入上传分片和合并对象，P0-07 已接入人物内容字段仓储并自动迁移旧人物 JSON，P0-08 已接入导入任务/清单事务仓储并自动迁移旧导入 JSON，P0-09 已接入单一本地 owner 会话和 owner 归属校验；随机人物和导入 ID 仍是明文非秘密索引。多用户账户、可配置保留期、数据导出、级联删除和审计仍属于后续生产化任务；在对应代码和测试完成前，不视为已提供。

## 6. 保留与删除

当前版本没有自动清理期限。人物资料、导入任务和清单、上传分片及合并后的文件会保留在启动参数 `--data-dir` 指定的目录中，直到本地操作者主动处理该目录。

当前应用内没有删除按钮或删除接口。如需在开发阶段删除数据，应先停止服务，确认目标确为本次运行配置的数据目录并自行备份必要内容，再删除对应的本地数据。未来的删除功能必须同时覆盖原始文件、解析结果、人物画像、长期记忆、向量、会话和受控训练产物。

## 7. 第三方模型与凭据

当前运行时适配器已覆盖 OpenAI、DeepSeek、小米 MiMo、阿里通义千问、Ollama 和自定义 OpenAI-compatible 服务。只有已配置的供应商和允许的模型才能处理请求。

Anthropic、Google Gemini 和自定义 HTTP 目前仅存在于供应商目录中，尚未实现可用的运行时适配器。目录中可见不代表已经能够发起请求；对应适配器和测试完成前，这些选项不能标记为可用。

发送给第三方模型供应商的数据可能包括所选模型、对话角色和文本消息。项目无法代替供应商承诺其存储地点、保留时间或训练用途；使用前应阅读相应供应商的最新条款。供应商价格和政策均可能变化，应以供应商公布的信息为准。

API Key 仅从服务端环境变量读取。当前前端不接收、保存或展示 API Key。部署者仍需负责保护运行环境、进程权限和日志，避免凭据通过其他方式泄露。

## 8. 微信数据库与学习功能的后续边界

微信数据库直接解析和模型学习尚未在当前项目中实现。后续接入时必须遵守以下边界：

- 仅处理用户主动选择并有权使用的数据；数据库、WAL 和 SHM 文件应先形成一致的只读快照，再进行解析。
- 如果解析确实需要密钥提取，必须作为单独的、用户明确授权的本地步骤执行；密钥只允许短暂存在于进程内存中，不得写入日志、配置或持久化文件。
- 训练、画像生成或外部模型处理开始前，必须说明使用的数据范围、处理位置、供应商和预计费用，并再次取得用户确认。
- 任何训练或模拟结果都不能用于主动联系、欺骗或代表被模拟人物作出现实承诺。

## 9. 使用者权利与责任

在当前本地开发形态下，使用者可以通过控制本地数据目录和模型配置决定是否继续处理数据。完整的应用内访问、更正、导出、删除和撤回同意流程尚未实现。

使用者应避免导入无权处理的第三方数据，并妥善保护运行设备、数据目录和模型凭据。如果将服务开放给其他设备或人员，部署者需自行增加 HTTPS、身份验证、访问控制和网络隔离；当前项目不自动提供这些能力。
