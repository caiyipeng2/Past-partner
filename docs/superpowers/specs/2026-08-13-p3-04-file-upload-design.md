# P3-04 移动端文件选择与可恢复分片上传设计

## 目标

在已验收的 Flutter 导入任务工作区中接入真实文件选择和可恢复分片上传，支持常见聊天原生文件、图片、音频、视频和其他文件，不把整个文件加载进内存。

## 范围

- 使用系统文件选择器选择一个或多个文件。
- 读取文件名、大小和 MIME 类型，提交多文件导入清单。
- 按服务端 8 MiB 分片协议串行上传，每次只读取一个分片。
- 上传前读取 `missing-chunks`，跳过服务端已持久化的分片。
- 每个分片带 SHA-256；失败时显示稳定重试入口。
- 全部分片完成后调用 `complete` 并刷新导入任务状态。
- 重新进入任务时允许重新选择并校验同一文件清单后继续上传。

## 非范围

- 操作系统后台任务、通知、并发上传和自动重试策略。
- 修改服务端上传协议、扩大服务端 3 GiB 限制或改变加密存储。
- 自动解析聊天数据库、媒体内容审核或训练数据生成。

## 架构

`FilePickerImportSource` 将平台文件选择器转换为可按范围读取的 `LocalImportFile`。`ImportUploadController` 负责选择、元数据创建、缺片查询、分片哈希/上传和完成；`ImportGateway`/`ApiClient` 只负责 HTTP 契约。页面通过可选控制器显示文件列表、百分比和稳定错误文案，原有无真实文件源的测试替身仍保留。

文件按选择顺序拼接成一个导入 payload。分片索引是整个导入任务的全局索引，默认 8 MiB，与后端 `DEFAULT_CHUNK_BYTES` 一致。断点恢复需要用户重新选择文件；控制器按名称、MIME 和大小校验后复用已有任务 ID。

## 错误与安全

- 用户取消选择不显示错误，也不创建空任务。
- 空文件清单、文件不可读、清单不匹配、网络错误、服务端稳定错误均转换为可重试的用户提示。
- 不把响应正文、访问令牌、本地完整路径写入 UI 或日志。
- 分片上传只保留当前分片字节；服务端继续执行 3 GiB 总量和单片上限校验。

## 验收

1. Android 真机可选择至少一个文件，显示名称/大小并创建对应导入任务。
2. 上传请求带正确分片索引、长度和 SHA-256，服务端已存在的分片会被跳过。
3. 网络失败后可重试；重新选择同一文件清单可从缺片继续，不匹配时拒绝继续。
4. 完成后任务状态刷新为服务端返回状态，不伪造完成状态。
5. Dart 分析、Flutter 全量测试、后端相关回归和 Android Debug/Release 构建通过。
