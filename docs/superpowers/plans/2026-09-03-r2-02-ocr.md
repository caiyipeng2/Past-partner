# R2-02 OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the remaining R2-02 slice by adding consent-gated, provider-capability-gated OCR for uploaded images with a bounded structured result.

**Architecture:** OCR is an image-processing operation, so the existing P1-10 consent remains `data_category=image`; the caller must use an exact OCR purpose/scope such as `persona-image-ocr`. A new `ocr` provider/model capability is independently configured with `PAST_PARTNER_<PROVIDER>_OCR_MODELS`, while the existing media-analysis service still owns owner checks, selected-file materialization, consent rechecks, and plaintext cleanup. OpenAI-compatible adapters reuse the vision chat endpoint and require a JSON object containing bounded text and optional OCR blocks; unsupported or malformed providers fail closed.

**Tech Stack:** Python 3 dataclasses, existing ProviderGateway/catalog/configuration, OpenAI-compatible JSON transport, AES-GCM UploadService streaming boundary, existing HTTP API, Flutter/Dart media-analysis client, unittest, local HTTP smoke tests.
