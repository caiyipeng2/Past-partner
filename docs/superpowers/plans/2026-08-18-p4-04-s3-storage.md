# P4-04 S3-Compatible Object Storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an explicitly configured, optional S3-compatible `BlobStore` adapter without changing logical object keys, encrypted metadata, or local default behavior.

**Architecture:** Keep `BlobStore` as the only upload-facing port. `S3BlobStore` receives an injected boto3-compatible client, validates logical keys and stream metadata, maps remote errors to stable `StorageError` codes, and never exposes provider messages or paths. `ServerConfig` validates S3 endpoint/bucket/credential settings, while application startup passes a typed settings value to the factory; missing boto3 or invalid configuration fails before any upload object is written.

**Tech Stack:** Python 3.11+, boto3/botocore optional storage profile, existing `BlobStore` protocol, unittest, CodeGraph.

- [x] **Step 3: Implement the minimal adapter**

Add `S3BlobStoreSettings`, `StorageBackendUnavailableError`, and `S3BlobStore`. Reuse the existing key and write-metadata validators; pass `ContentLength`, a SHA-256 metadata value, and `IfNoneMatch="*"` on writes. Use a bounded hashing reader so the adapter never reads an entire object into memory. Delete a just-written object if stream length or digest verification fails. Keep `LocalBlobStore` behavior unchanged and make `build_blob_store("s3", ...)` import boto3 lazily, raising `storage_backend_unavailable` if the optional profile is absent.
