# P3-10 移动端隐私管理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Flutter 移动端提供可审阅的数据导出摘要和人物级删除流程，复用现有 owner 会话、`GET /api/v1/data-export` 与 `DELETE /api/v1/personas/{persona_id}`，不把原始正文或访问令牌落入客户端持久化。

**Architecture:** 服务端现有隐私边界继续作为唯一数据来源；客户端新增 `PrivacyGateway`、`PrivacyController` 和 `PrivacyScreen`，将导出响应压缩为数量和范围摘要，避免把完整导出 JSON 放入界面状态。隐私入口放在人物工作区 AppBar，人物删除必须经过明确的二次确认并在成功后刷新人物列表。

**Tech Stack:** Flutter/Dart、Material 3、现有 `ApiClient`/`SessionController`、Flutter widget/unit tests。

## Self-review

- Existing server export/delete endpoints are reused; no duplicate backend privacy contract is introduced.
- Client parsing is count-only and bounded, so raw message bodies and provider-side metadata are not retained in UI state.
- Destructive deletion is explicit, scoped to one persona, and followed by a list refresh.
- The design follows the existing chat/persona Material 3 visual language while applying the generated privacy palette as semantic status accents rather than adding a separate visual theme.
