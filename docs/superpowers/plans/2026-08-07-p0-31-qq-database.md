# P0-31 QQ 数据库安全解析实现记录

## 目标

对照原始产品大纲，为用户主动选择的 QQ 数据库目录提供可复用的明文 SQLite 解析入口，输出项目统一的 `NormalizedMessage`。本任务只覆盖已识别的通用消息表导出，不猜测 QQ 专有加密格式或隐式会话关系。

## 实现边界

- 新增 `qq_database` parser，支持目录内 `.db` 文件和现有 `-wal`、`-shm` sidecar 的一致只读快照。
- 通过 SQLite 只读 URI 和 `PRAGMA query_only=ON` 查询，源目录不写入；快照期间源文件持续变化时返回稳定的 `snapshot_changed` 错误。
- 识别消息表名 `Message`、`Messages`、`QQMessage`、`ChatMessages`、`Msg` 等，以及发送者、内容、时间的常见字段别名；消息 ID、昵称、类型和会话 ID为可选字段。
- 支持文本、图片、音频、视频、文件、表情等消息类型映射，统一输出 `NormalizedMessage` 和服务端稳定 `record_id`。
- 单个 `.db`、非 SQLite/加密库、未知 schema 和空消息目录拒绝解析，不自动提取、猜测或持久化密钥。
- 浏览器分片上传仍按文件建立独立导入任务；目录聚合和 QQ 专有备份/媒体格式不在本任务范围。

## 验收证据

`tests/unit/test_qq_database.py` 覆盖明文消息标准化、常见字段别名、源文件只读、单文件拒绝、未知 schema、加密库、损坏 SQLite、WAL/SHM 快照和源变化重试。完整 `npm test` 与 CodeGraph 回归在实现收口后执行。
