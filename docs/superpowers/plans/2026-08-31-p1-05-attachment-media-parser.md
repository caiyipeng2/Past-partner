# P1-05 附件与媒体引用元数据解析

## 目标

按已确认的 P1 顺序，把 JSON/JSONL、CSV、XML、HTML 和通用 SQLite 消息中的附件引用统一为 `NormalizedMessage.attachments` 元数据。此任务只处理引用和可审计元数据，不读取媒体内容，也不触发第三方模型调用。

## 范围

- 识别图片、音频、视频、文件和贴纸引用。
- 统一相对路径或 HTTP(S) URL、文件名、MIME 类型、类型、大小和可选 SHA-256。
- 支持 CSV 附件列、XML 媒体元素、HTML `img/audio/video/source/a` 引用和 SQLite 常见附件列。
- 拒绝绝对路径、路径穿越、内嵌 `data:` 原始字节、负大小和原始字节字段。
- 允许只有附件而没有正文的消息通过规范化。

## 明确不在本任务

- 不读取、解码、缩略、OCR、ASR、视觉分析或上传图片、音频、视频和文件。
- 不实现微信/QQ 私有媒体数据库、浏览器目录聚合、媒体授权 UI、费用估算或模型调用。
- 不把本地文件系统绝对路径暴露给预览或后续模型上下文。

## 验收标准

1. JSON/JSONL、CSV、XML、HTML 和通用 SQLite 的附件引用输出同一组安全字段。
2. MIME 可由显式字段或扩展名推断，类型可由 MIME、消息类型或引用名称推断。
3. 路径穿越、绝对路径、内嵌原始字节和非法大小返回稳定 `invalid_record` 失败，不产生部分成功记录。
4. 解析器不打开附件引用指向的文件；现有消息解析、预览限制、记录 ID 和数据库只读快照测试保持通过。
5. 文档明确媒体内容分析与第三方发送仍需后续授权流程。
