# P3-09 移动端真实聊天与会话历史实施计划

## 目标

依据已确认的 Phase 4 移动端大纲，将当前仅有的静态对话预览和无状态 `POST /api/v1/chat` 收口为一条可验收链路：会话按 owner/persona 隔离并使用现有认证加密 SQLite 持久化，Flutter 可以创建会话、恢复历史、发送消息并显示明确的加载/失败/重试状态。聊天页提供两套可切换的对话外观，分别延续已验收的简洁微信式和活泼 QQ 式布局，但不在界面文案中暗示官方关联。

## 范围边界

- 增加 `conversations` 加密仓储和数据库迁移；删除人物时级联清理本地会话。
- 增加 `POST/GET /api/v1/conversations`、`GET /api/v1/conversations/{id}`、`POST /api/v1/conversations/{id}/messages`。
- 发送接口只接收用户消息正文，由服务端使用会话选定的 provider/model 调用统一 ProviderGateway；provider 失败时不落库半条用户消息。
- 保留原 `/api/v1/chat` 供现有调用方使用，避免把通用无状态接口与会话状态耦合。
- Flutter 增加真实会话模型、网关、控制器和聊天页；支持刷新历史、发送、失败重试、禁用重复提交和空消息拦截。
- 本任务不实现 SSE/流式适配、语音/图片/视频/位置/红包/通话等媒体动作，不实现隐私管理页；这些能力必须在后续任务有独立验收标准后再加入。

## TDD 验收顺序

1. 先写后端域模型、仓储、HTTP/API 失败测试；运行
   `python -m unittest tests.unit.test_conversations tests.unit.test_conversation_repository tests.integration.test_conversation_api -v`，确认测试先因缺少实现而失败。
2. 实现迁移、加密仓储和服务边界；重复运行上述后端测试，确认 owner/persona 隔离、未知会话 404、provider 失败不产生半条消息、人物删除级联和历史顺序均通过。
3. 先写 Flutter API client、controller 和 widget 失败测试；通过 ASCII `subst` 映射执行
   `flutter test test/core/network/api_client_test.dart test/features/chat/chat_controller_test.dart test/features/chat/chat_screen_test.dart test/features/persona/persona_workspace_screen_test.dart`。
4. 实现真实聊天页：顶部人物/模型信息、历史气泡、发送栏、清晰的重试入口；使用 `Semantics`、最小 48dp 触控区、安全区和 8dp 间距，不使用 emoji 作为结构图标。
5. 运行 `dart analyze --format=machine`、完整 `flutter test`、Python `npm test`；必要时通过 `Q:` 映射避免中文路径导致 Flutter/CMake 工具链失败。
6. 构建并清理旧 APK：
   `scripts/build_mobile_apk.ps1 -ProjectRoot Q:\ -OutputDirectory E:\Tools`，确认仅保留最新 `Past-partner_<version>_<yyyyMMdd_HHmm>_{debug,release}.apk`，安装 debug 包到已连接安卓真机并完成手工聊天验收。

## 用户验收标准

- 进入人物工作区后能看到“开始对话”入口；未选模型时能明确引导选择模型，不会发送空 provider/model。
- 首次进入创建 owner/persona 隔离的会话，刷新或重新打开仍能看到历史消息；另一人物看不到该会话。
- 发送一条非空消息时显示发送中状态，服务端返回的 assistant 内容以对方气泡显示；重复点击不会产生重复请求。
- provider 不可用时显示可读错误和重试按钮，历史中不会出现伪造的 assistant 回复。
- 简洁/活泼外观切换会复用已验收的视觉语言；浅色背景下正文对比度足够，底部输入栏不被系统导航区遮挡。
- P3-09 提交后保持分支未合并；用户确认后才合并 `main`、回归测试并推送远端。
