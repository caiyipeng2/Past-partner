# P1-10 媒体第三方处理授权

## 目标

按原始 P1 任务表独立收口 P1-10：为图片、音频和视频等原始媒体的第三方模型处理建立可查询、可撤回、按作用域隔离的授权记录。授权记录本身使用现有 AES-GCM 加密仓储，并绑定当前本地 owner 与人物。

## 本任务范围

- 保存供应商、模型、数据类别、用途、预计费用、授权范围、创建时间和状态。
- 只有 provider、model、data category 和 authorization scope 完全匹配的有效记录才能通过授权校验。
- 同一人物的相同 active 作用域不得重复创建；撤回后保留记录但禁止再次授权。
- 提供 `POST /api/v1/consents`、`GET /api/v1/consents` 和 `POST /api/v1/consents/{consent_id}/revoke`。
- 所有接口执行 owner 与人物归属校验；人物删除和 owner 数据导出覆盖授权记录。
- 本地上传、解析和保存媒体引用不等于向第三方发送，也不要求提前创建第三方授权。

## 不在本任务范围

- 不在本任务触发 OCR、ASR、视觉理解、视频分析或真实模型调用。
- 不在本任务实现供应商价格实时查询、模型能力目录或前端授权页面。
- 撤回仅阻止未来使用本地记录发起处理，不代表第三方已经接收的数据会被自动删除。

## 验收标准

1. 授权记录字段校验、加密持久化、读取和撤回均有单元测试。
2. 创建、列表、撤回、缺字段和人物删除清理均有 HTTP 集成测试。
3. 授权作用域不完全匹配、重复 active 记录和已撤回记录都会稳定拒绝。
4. 数据库从空库和历史版本迁移到 v5，重复迁移和并发迁移保持幂等。
5. 隐私政策明确区分本地上传、第三方处理授权和撤回后的数据边界。
