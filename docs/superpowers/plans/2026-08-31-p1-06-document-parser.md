# P1-06 DOCX/PDF 对话文档解析

## 目标

按原始设计中的文档导入能力，为包含聊天记录或文字转录的 DOCX/PDF 文件增加 `generic_docx` 和 `generic_pdf` 解析器，并输出项目统一的 `NormalizedMessage`。

## 范围

- DOCX：只读取安全 ZIP 包中的 `word/document.xml`，提取段落文本并识别时间、发送者和正文。
- PDF：优先使用可选 `pypdf` 提取页面文本；依赖不可用时允许有界的纯文本 PDF 操作符回退。
- 文档扩展名/文件头优先于通用 TXT 探测，避免损坏 PDF/DOCX 被伪装为普通文本。
- 对损坏、加密、路径穿越、嵌套压缩包、超限、无对话内容返回稳定错误。
- 解析过程不执行文档脚本，不读取文档外部引用，不处理文档内媒体内容。

## 明确不在本任务

- 不实现 `.doc` 二进制格式转换。
- 不实现 PDF/DOCX 版式还原、OCR、表格语义恢复、图片理解或媒体上传。
- 不把文档原始载荷发送给第三方模型，也不自动解密受保护文档。

## 验收标准

1. DOCX 对话段落和文本 PDF 对话内容可输出统一消息记录，并保留稳定 `record_id`。
2. DOCX ZIP 路径穿越、嵌套 ZIP、符号链接和超限条目会被拒绝。
3. PDF 头校验、加密检测、页数/大小限制和无文本错误边界明确。
4. 可选 `pypdf` 缺失时，简单纯文本 PDF 仍可用；复杂 PDF 则返回可行动错误而不是空成功。
5. 现有 270 个 Python 测试、4 个 Node 测试、编译检查和 CodeGraph 校验保持通过。
