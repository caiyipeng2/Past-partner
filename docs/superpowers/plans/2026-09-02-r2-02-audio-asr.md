# R2-02 Audio ASR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an explicit, consent-gated audio transcription path for OpenAI-compatible providers without advertising audio capability for models that have not been configured to support it.

**Architecture:** Keep the existing `MediaAnalysisService` and HTTP route as the owner/consent/payload boundary. Extend provider configuration and catalog wiring with an explicit per-model `audio` capability, then let `OpenAICompatibleAdapter` send the controlled temporary file to the standard `/audio/transcriptions` multipart endpoint and normalize only its bounded `text` result into the existing media-analysis description field. Image analysis remains unchanged; video and OCR remain separate follow-up slices.

**Tech Stack:** Python 3, existing `ProviderGateway`, `ProviderCatalog`, `urllib_multipart_transport`, AES-GCM `UploadService`, SQLite metadata contracts, unittest, local HTTP subprocess/thread smoke.
