# P2-04 长期记忆候选

## 目标

按 Phase 3 混合学习架构，从规范化聊天消息中提取可审核的 Relationship Memory 候选，为后续提示词、检索和持续学习提供事实边界。

## 本次范围

- 从 `NormalizedMessage` 提取事实、事件、关系、偏好和时间线候选。
- 支持只处理预览审核后传入的 `accepted_record_ids`，未传入时仍将候选标记为 `needs_review`。
- 每条候选保留稳定 `memory_id`、有限证据文本、来源 `record_id`、时间、置信度、说话人范围和审核状态。
- 合并相同候选的多个证据，限制候选数量和证据文本长度，拒绝无证据记录。
- 提供不可变的 `accepted`、`rejected`、`needs_review` 审核转换，并通过 `ChatDataParser.generate_long_term_memory` 接入规范化解析链路。

## 不在本次范围

- 不调用 DeepSeek、通义千问、Gemini 或其他模型做语义推断，不上传原始聊天内容。
- 不实现记忆持久化、独立 API、向量索引、提示词编排或 Flutter 页面。
- 不把候选直接视为事实；只有显式审核后的候选才能由后续学习层消费。

## 验收标准

1. 事实、事件、关系、偏好和时间线均可由规范化消息生成，未选中的 `accepted_record_ids` 不得影响候选。
2. 候选默认 `needs_review`，保留稳定 ID、有限文本、来源记录、时间、置信度和说话人范围；相同候选合并证据。
3. 缺少 `record_id`、未知已接受记录、非法审核状态、非法关系或超出候选上限时返回稳定错误码。
4. 审核操作返回新对象，不修改原始候选集合；解析门面只返回记忆候选和来源类型。
5. 定向测试、完整 Python/Node 回归、编译检查和 CodeGraph 同步通过。
